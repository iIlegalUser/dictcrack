# dictcrack — 压缩包密码字典测试工具

用字典文件多线程并行测试 RAR / ZIP / 7Z 压缩包的密码，找到即显示并保存。

两种启动方式（同一图形界面）：

- **`dictcrack-gui.vbs`** — 推荐，双击启动，**全程无任何控制台窗口**
- **`dictcrack-gui.bat`** — 批处理启动器，功能相同但启动瞬间会闪一下 cmd 窗口

## GUI 用法（dictcrack-gui.vbs / .bat）

1. 双击 `dictcrack-gui.vbs` 打开窗口（推荐，PowerShell 控制台完全不可见；
   用 .bat 启动则会有短暂黑窗闪现）
2. 分别点"浏览..."选择压缩包和字典文件；**也可直接把压缩包 / 字典文件
   拖进窗口**（按扩展名 rar/zip/7z、txt/dic/lst 自动填入对应输入框，
   一次拖入多个会同时填两框）；输入框已有路径时，
   文件选择对话框会直接定位到该路径所在目录
3. "解压工具"下拉框自动列出检测到的 WinRAR（rar.exe / unrar.exe）
   和 7-Zip（7z.exe）及完整路径，默认"自动检测"按压缩包类型选择；
   也可点"浏览..."手动指定任意 exe（rar/unrar 只支持 RAR，
   选其处理 zip/7z 会被拦截提示）
3b. "并行线程"下拉框默认自动（逻辑核数的一半，上限 12），
   也可固定为 1~32 之间的任意线程数（不在列表中的值可通过
   命令行 `-Threads N` 使用）；运行时状态栏显示实际线程数
4. 点"开始破解"（或按 **Enter**），多线程并行测试字典，进度条显示当前遍
   进度、已尝试数量，状态区实时显示并行线程数、当前测试的密码、
   已用时、速度（个/秒）和预计剩余时间
5. 找到后"破解结果"栏绿色高亮显示密码，点"复制密码"即可使用；
   密码同时保存到脚本所在目录的 `<压缩包名>_password.txt`
   （不会在压缩包所在目录产生文件）
6. 可点"**密码提前到字典首行**"：把找到的密码移到字典文件第 1 行
   （自动去除重复行），下次破解同来源压缩包时第一个命中；
   按命中时的编码读写字典，UTF-8 / UTF-8 BOM / ANSI / UTF-16LE
   及 BOM 状态均保持不变，写入采用临时文件原子替换
7. 中途可点"停止"或按 **Esc** 取消；结束后统计行显示总计尝试数、
   总用时和平均速度

窗口可以横向拖宽（控件自动跟随），高度固定。

GUI 会**记住上次成功开始破解时使用的压缩包、字典路径、解压工具和线程数选择**
（保存在脚本旁的 `dictcrack-gui.cfg`），下次打开自动填入；
命令行 `-Arch`/`-Dict`/`-Tool`/`-Threads` 参数优先于记忆值。

GUI 由 PowerShell + WinForms 实现（`dictcrack-gui.ps1`，需保留 UTF-8 BOM 编码），
无第三方依赖。也支持带参数启动并自动开跑：

```bat
dictcrack-gui.bat -Arch secret.rar -Dict passwords.txt [-Tool 7z.exe完整路径] [-Threads 4]
```

## 依赖工具

GUI 自动按下面顺序探测工具（常用安装目录 + PATH）：

| 压缩包类型 | 优先使用 | 备选 |
|---|---|---|
| `.rar` | WinRAR 的 `rar.exe` | `unrar.exe` → 7-Zip `7z.exe` |
| `.zip` / `.7z` | 7-Zip `7z.exe` | — |
| 其他（cab、iso 等） | 7-Zip `7z.exe` | `rar.exe` |

注意：WinRAR 的**控制台**程序 `rar.exe` / `unrar.exe` 只能处理 RAR 格式，
ZIP / 7Z 必须用 7-Zip。两者都没装的话 GUI 会报错并停在待机状态。
（WinRAR GUI 主程序 `WinRAR.exe` 无法命令行传密码，所以用不了它。）

## 字典文件格式

- 每行一个密码（可含空格和 `&`、`!`、`#` 等特殊字符，已实测）
- 空行自动跳过
- 以 `;` 开头的行视为注释
- 密码中含双引号 `"` 的同样支持（自动转义）

### 编码自动兼容（UTF-8 优先）

字典编码**无需手动转换**，GUI 自动按下表处理，**UTF-8 优先**：

| 字典编码 | 处理方式 |
|---|---|
| UTF-8 无 BOM | 先严格校验文件头 256KB：合法则第一遍按 UTF-8 解码读取，即可命中 |
| UTF-8 带 BOM | 检测到 BOM 后直接按 UTF-8 读取 |
| ANSI/GBK（无 BOM） | 文件头校验判定非 UTF-8 时直接按 ANSI 单遍处理（跳过必然失败的 UTF-8 遍，省一半时间）；碰巧合法 UTF-8 的 GBK 字典仍保留双遍兜底，不会漏密码 |
| UTF-16LE | 检测到 BOM 后直接按 UTF-16LE 读取 |
| UTF-16BE | 不支持，提示重新保存后重试 |

第二遍只在第一遍没找到时才运行，UTF-8 字典（目前最常见）不会有额外开销。
BOM 检测与编码探测只读文件头 256KB，超大字典也没有额外开销。
注意：结果文件 `<压缩包名>_password.txt` 按系统代码页（GBK）写入，中文正常。

## 找到密码后手动解压

```bat
rar   x -p"密码" "xxx.rar" "D:\输出目录\"
7z    x -p"密码" -o"D:\输出目录" "xxx.7z"
```

## 速度说明

**并行破解**：默认按机器自动选择并行度（逻辑核数的一半，上限 12 线程），
也可在"并行线程"下拉框固定线程数（或命令行 `-Threads N`）。
字典切片后多线程同时测试，任一线程命中立即停止其余线程。
实测 24 线程机器约 **100~160 个/秒**（单线程约 14 个/秒，提升 7~10 倍）；
状态栏会显示当前并行线程数。多编码遍（UTF-8 / ANSI）逐遍执行，每遍内部并行。

更大的字典建议用专业工具（John the Ripper、hashcat、ARCHPR 等），
速度快几个数量级。

## 注意

- `dictcrack-gui.bat` 内容为纯 ASCII，避免 GBK 代码页下 cmd 解析乱码，
  请勿往里添加中文。
- 请仅用于测试自己拥有或已获授权的文件。
